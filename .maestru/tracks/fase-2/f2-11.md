# F2-11: Catálogo de componentes do frontend a partir da API (remover ficheiro estático)

## Objetivo

Apagar `packages/circuit-schema/catalog/components.json`. Este ficheiro é hoje a única fonte
estática de catálogo que ainda existe no repositório (o backend já foi migrado para MongoDB em
F2-10). O frontend (`apps/web`) importa-o em build-time em `editor/catalog.ts`; antes de apagar
o ficheiro, o frontend tem de passar a carregar o catálogo de `GET /api/v1/components` em tempo
de execução.

## Plano validado

Ver `f2-11-spec` para a análise de impacto completa (ficheiros afetados, confirmados por
grep/leitura direta) e o plano de implementação faseado:

- **Fase 1** — `editor/catalog.ts` passa a expor um singleton populado via `loadCatalog()`
  (novo `GET /api/v1/components` em `api/client.ts`), carregado uma vez no arranque da app
  (`App.tsx`), antes de montar o editor. Os 13 ficheiros que hoje consomem `catalog`/
  `GRID_SIZE`/`getComponentDefinition` de forma síncrona **não precisam de alterações**.
- **Fase 2** — depois de validada a Fase 1: apagar `packages/circuit-schema/catalog/components.json`,
  remover o respetivo export em `package.json`, e atualizar `test/catalog.test.mjs` (que hoje lê
  o ficheiro para validar o schema/fixtures).

## Critérios de aceitação

- [ ] `apps/web` carrega o catálogo de componentes via API, não de um ficheiro estático
- [ ] `packages/circuit-schema/catalog/components.json` apagado
- [ ] Sem nenhuma referência de produção remanescente a `catalog.json`/`catalog/components.json`
- [ ] `pnpm --filter @vcccircuitlab/web test` e `pnpm --filter @vcccircuitlab/circuit-schema test` passam
- [ ] `maestru check` sem erros
