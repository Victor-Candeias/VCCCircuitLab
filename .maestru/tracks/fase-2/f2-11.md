# F2-11: Catálogo de componentes do frontend a partir da API (remover ficheiro estático)

## Objetivo

Apagar `packages/circuit-schema/catalog/components.json`. Este ficheiro é hoje a única fonte
estática de catálogo que ainda existe no repositório (o backend já foi migrado para MongoDB em
F2-10). O frontend (`apps/web`) importa-o em build-time em `editor/catalog.ts`; antes de apagar
o ficheiro, o frontend tem de passar a carregar o catálogo de `GET /api/v1/components` em tempo
de execução.

## Plano validado

Ver `f2-11-spec` para a análise de impacto completa (ficheiros afetados, confirmados por
grep/leitura direta) e o plano de implementação faseado:

- **Fase 1** — `editor/catalog.ts` passa a expor um singleton populado via `loadCatalog()`
  (novo `GET /api/v1/components` em `api/client.ts`), carregado uma vez no arranque da app
  (`App.tsx`), antes de montar o editor. Os 13 ficheiros que hoje consomem `catalog`/
  `GRID_SIZE`/`getComponentDefinition` de forma síncrona **não precisam de alterações**.
- **Fase 2** — depois de validada a Fase 1: apagar `packages/circuit-schema/catalog/components.json`,
  remover o respetivo export em `package.json`, e atualizar `test/catalog.test.mjs` (que hoje lê
  o ficheiro para validar o schema/fixtures).

## Critérios de aceitação

- [x] `apps/web` carrega o catálogo de componentes via API, não de um ficheiro estático
- [x] `packages/circuit-schema/catalog/components.json` apagado
- [x] Sem nenhuma referência de produção remanescente a `catalog.json`/`catalog/components.json`
- [x] `pnpm --filter @vcccircuitlab/web test` e `pnpm --filter @vcccircuitlab/circuit-schema test` passam
- [x] `maestru check` sem erros

## Implementação

- `editor/catalog.ts` expõe `setCatalog()`/`isCatalogLoaded()`; `catalog`, `GRID_SIZE` e
  `UNKNOWN_COMPONENT_SIZE` são live bindings ESM e `getComponentDefinition` falha com
  "Catálogo não carregado" antes do arranque. `PASTE_STEP` do `editorStore` passou a ser
  calculado em runtime.
- `api/client.ts`: `getComponents()` (`GET /api/v1/components`). `App.tsx` carrega o catálogo
  depois do login e antes de montar o editor (ecrã de carregamento/erro com "Tentar novamente").
- Fase 2: `catalog/components.json` foi movido para `test/fixtures/catalog.json` (opção b do
  spec) e exportado só como `./fixtures/catalog.json`, usado por `catalog.test.mjs`, pelo
  `test/setup.ts` do `apps/web` e pelo mock do E2E com `PLAYWRIGHT_SKIP_BACKEND=1`.
- Nota: numa instalação nova a coleção `templates` tem de ser povoada (via `/api/v1/templates`)
  para o editor arrancar.
